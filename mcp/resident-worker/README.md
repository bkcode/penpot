# Resident MCP worker

Keeps one Penpot design file available to MCP without an open desktop browser. A supervised headless Chromium runs the existing editor and bundled MCP plugin. Penpot still uses its normal backend, permissions, file format and renderer.

This module is maintained in `git@github.com:bkcode/penpot.git`. It can run alongside Penpot 2.18.5 without rebuilding or migrating the core application.

## Run

Use the single [`compose.yaml`](../../compose.yaml) at the repository root. Setup, account permissions, credentials and startup commands are documented in [Local deployment](../../LOCAL-DEPLOYMENT.md).

The worker has a dedicated account, editor access to one team/file, and its own MCP key. Its credentials are mounted read-only from the ignored root `.worker-credentials.json`. The page ID is the initial page; normal MCP operations can switch pages within the same file.

The root deployment caps worker memory at 4 GiB; this is a limit, not a reservation. The worker exposes no host port. It connects to `http://penpot-frontend:8080` on the private Compose network. It uses a fresh browser context after each recovery and does not read desktop browser profiles, cookies or passwords.

## Health and recovery

- `GET /healthz`: process liveness.
- `GET /readyz`: returns 200 for a verified target or a connected plugin executing a task (`ready` / `busy`). Returns 503 during startup, probe degradation or recovery. A failed probe does not itself close the browser.
- The worker observes MCP WebSocket task requests, responses and plugin heartbeats. While a business task is active, it skips the competing execution probe for up to 150 seconds (the default 120-second MCP deadline plus 30 seconds). Health probes do not count as business tasks.
- An isolated probe failure changes readiness to `degraded` and retains the browser, file and pending tasks. Recovery requires both 3 consecutive failures and 150 seconds since the first failure. A successful read or a connected busy task clears the failure streak.
- Confirmed browser/process/page loss, including a renderer `crash` event while Chromium stays connected, recovers on the next check without the probe grace period. A crash during a pending probe is also classified as browser loss once the probe settles. Plugin disconnects get the grace period so normal WebSocket reconnection can repair the connection without discarding the editor.
- A task that never answers is not protected forever: after its task budget, active probes resume; sustained failures can then trigger recovery. The grace period starts at the first failed probe, so this path can take longer than 150 seconds.
- `PENPOT_WORKER_FAILURE_THRESHOLD`, `PENPOT_WORKER_RECOVERY_GRACE_MS`, and `PENPOT_WORKER_TASK_BUDGET_MS` configure these budgets. The latter two must be at least 120 seconds; align them with the MCP task deadline when changing its default.
- Defaults: 15-second read checks, 5-second recovery delay, 90-second startup budget. `PENPOT_WORKER_CHECK_INTERVAL_MS`, `PENPOT_WORKER_RETRY_INTERVAL_MS` and `PENPOT_WORKER_STARTUP_TIMEOUT_MS` override these values.
- `SIGTERM` closes Chromium and the MCP probe session. Docker supplies the container restart policy. An unhealthy container is not itself a restart trigger; the recovery loop repairs browser/plugin failures.
- The Mac/Docker host must stay awake. Resuming the host allows recovery; this service does not prevent system sleep or provide pre-login boot management.

```bash
docker exec penpot-penpot-worker-1 node -e \
  "fetch('http://127.0.0.1:4404/readyz').then(async r=>console.log(r.status,await r.text()))"
```

## Internal origin

The public instance may use a LAN hostname that containers cannot reach. Inside its own context, the worker replaces `penpotPublicURI` in `/js/config.js` with the internal origin. Asset URLs generated by this instance are fetched through the authenticated internal origin. Other origins and non-asset paths are left alone.

Chromium treats only the configured internal origin as trustworthy so the editor's secure-context APIs work over the private HTTP network. This does not turn off web security or change the public frontend. Use this worker only with a trusted Penpot instance; its account can execute the normal plugin operations permitted by that account.

The image reuses the matching exporter image's Chromium and system libraries, with Playwright pinned to 1.62.1. If the base image changes, check the bundled Playwright version before updating the dependency. Credentials are mounted read-only. Logs contain timestamps, fixed failure reason codes, failure counts and elapsed time; raw browser/network errors, scripts and MCP URLs are not logged. Readiness exposes pending task count and last plugin activity, but no task content.

## Development

This is a standalone package so installing it does not update the MCP server/plugin dependency graph.

```bash
cd mcp/resident-worker
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 pnpm install --ignore-workspace --frozen-lockfile
pnpm run test
pnpm run types:check
pnpm run fmt:check
pnpm run build
```

Runtime and tests require Node 24+. Unit tests cover configuration validation, secret-safe failures, MCP JSON/SSE handling, task/heartbeat observation, isolated probe failure, recovery thresholds and grace, busy readiness, shutdown and asset routing. For live acceptance, use a disposable design file: write/read a marker, export an existing board, kill only the worker's browser, restart the worker/MCP, then read the marker again and remove it.

## First-version scope

One worker owns one file. It does not expose a file-switch API, accept arbitrary URLs, or run a multi-file queue. To use another file, update its target IDs and recreate the worker. Ordinary page changes within the target file are allowed.

## Image download DNS repair

If the host proxy returns Fake-IP DNS answers in `198.18.0.0/15`, Penpot rejects remote image downloads. The root Compose deployment gives only the backend a private DNS-over-HTTPS resolver while retaining all SSRF checks. See [DNS repair](DNS.md). It is independent of worker recovery and needs a backend recreation when enabled.
